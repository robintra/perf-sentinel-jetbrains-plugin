# Security policy

## Supported versions

Only the latest stable `0.x.y` release receives security fixes. If no stable
release is public yet, reports still apply to the current `main` branch.

## Reporting a vulnerability

Use GitHub private vulnerability reporting from the repository Security page.
Include the affected version or commit, IDE and operating system, impact,
reproduction steps, and any suggested mitigation.

Do not open a public issue, discussion, or pull request for an undisclosed
vulnerability. Do not include credentials, private keys, access tokens, or
personal data in a report. If GitHub private vulnerability reporting is not yet
available while the repository is private, wait for public activation rather
than posting sensitive details publicly.

The maintainer will acknowledge a usable report, reproduce it privately, and
coordinate a patch and disclosure. Timelines depend on severity and JetBrains
Marketplace review. Please allow a reasonable remediation period before public
disclosure.

Ordinary bugs without a security impact belong in the public bug report form.
